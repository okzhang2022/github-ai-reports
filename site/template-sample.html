NO. 01 · 逆向分析

REA

+151,78410.13 → 10.18 净增

morluto/rea

让 Agent 沿着程序证据解释功能

把应用、打包后的 JavaScript 或原生程序交给 Agent，通过 MCP 调用分析工具，追踪功能实现。输入是待分析程序和问题，输出是调用链、证据与解释。

什么时候用

  • 分析自己维护的 Electron 应用中的剪贴板逻辑
  • 在缺少完整源码时定位某项功能的实现路径

适合谁

维护桌面应用、研究程序行为的工程师

与你的关系　可借鉴“结论附证据”的设计，用于代码理解和问题定位；常规前端开发可按需关注。

使用 Demo

官方文档整理 · 未实测

准备　Node.js、兼容的 Agent 与可用模型。原生分析可能需要 Ghidra、Hopper 或 IDA；静态 JavaScript 分析不要求原生引擎。

安装 / 配置 · 官方文档
npx rea-agents setup
  1. 按安装向导连接你的 Agent，并准备一个自己维护的 Electron 应用。
  2. 把应用路径替换到下方任务中，要求 Agent 先给证据，再给结论。
示例输入 · 本报告编写
用 REA 分析我提供的 Electron 应用。追踪“复制富文本”从页面入口到系统剪贴板的调用链，列出相关文件、函数与证据；无法确认的环节请单独说明。
预期结果

得到可回查的函数与文件位置、IPC 流向和剪贴板写入说明；具体内容取决于目标应用。

模型使用可能产生费用；此例不包含应用文件，也未执行分析。

+4,36010.13 → 10.18 净增

DietrichGebert/ponytail

让 Agent 先找现有能力，再决定写多少代码

通过技能指引 Agent 复用已有实现、避免过度设计，并提供代码审查与仓库审计能力。输入是任务或改动，输出是实现建议和问题清单。

什么时候用

  • 审查分支改动中的 bug 与不必要抽象

适合谁

希望减少维护负担的研发人员

与你的关系　适合与你的 Review 工作流做方法对照，观察精简实现与必要校验、测试之间的边界。

使用 Demo

官方文档整理 · 未实测

准备　受支持的 Agent 宿主与可用模型。示例采用官方 Claude Code 插件入口。

安装 / 配置 · 官方文档
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail
  1. 在 Claude Code 中分次运行两条安装指令。
  2. 打开一个有未提交改动的练习项目，运行 /ponytail-review。

示例输入 · 本报告编写

预期结果

一组带原因与修复方向的审查发现；不保证一定存在问题，也不等同于完成验证。
